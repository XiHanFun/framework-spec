# XiHan Spec 变更记录整理

## 事实源

- 用户指定的起止标签或提交；未指定时先列出最近的规范标签（`git tag -l 'v*'`）和当前 HEAD；还没有标签时，以「未发布」一节已记的最早一条为起点往后核对（更早的修订记在各 RFC 状态行与 ADR 里，不逐条重列）。
- 范围内的提交说明（末尾的 ADR 编号）、实际 diff、RFC 状态行新增的修订记录、档表与向量的变化。
- 对应的 ADR（XiHan.Framework 的 `plans/adr/`），用来确认取舍与级别。
- `CHANGELOG.md` 现有的格式：「未发布（vX.Y.Z）」一节，最新的在最上面，一条一行 `- <级别>：<主题>：<要点>（ADR-NNNN）。`

## 收录规则

- 改动规范性内容的提交都要有一条（RFC-0024「版本」第 6 条）：正文、Schema、协议、向量的期望值与用例、档表、运行器用例。
- 级别按 RFC-0024 界定：PATCH 不改规范性内容；MINOR 只增或写死以前不作规定的行为；MAJOR 改已写明的、删除、线上不兼容、把向量移出档。`v1.0.0` 之前的 MAJOR 写「MAJOR（`v1.0.0` 之前允许）」。
- 措辞、示例、.NET 映射等 PATCH 级改动对实现者有用时也记一条（如 ADR-0244）；只改 README、AGENTS.md、技能或 CI 的提交不记。
- 每条写实现者要知道的结果：哪份规范、哪一节、哪个向量文件，读写两侧各要怎么做；不罗列内部函数名，除非它是 Go 一致性模块的公开入口。
- 同一 ADR 的多个提交合成一条；同一提交跨两个级别时按最高的级别记，要点里分开写。

找到漏记或级别不符的条目时列给用户确认后再改；本技能不改规范正文、不改版本号、不打标签。
