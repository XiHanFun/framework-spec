# RFC-0022 AI：聊天、嵌入、工具与知识

> 状态：已采纳 | 日期：2026-10-26 | 对应 ADR：ADR-0017 | 参考实现：`XiHan.Framework.AI.Abstractions`、`XiHan.Framework.AI.OpenAI`、`XiHan.Framework.AI.VectorData` | 一致性：`XiHan.Framework.AI.Conformance`

## 摘要

AI 子系统以 `Microsoft.Extensions.AI` 的 `IChatClient` / `IEmbeddingGenerator` / `AITool` 为线格式，不另造模型接口：框架提供按名字解析模型 Provider 的目录、带提示词 / 护栏 / 工具的聊天入口、把 `[Operation]` 契约桥接成模型可调用工具的目录，以及"切块 → 嵌入 → 向量存取 → 检索 → 提示增强"的知识库流水线。模型端点与向量存储都是外部资源，由 Provider 包适配；进程内的工具目录零外部依赖。能力 `ai.chat@1`、`ai.embedding@1`、`ai.tools@1`、`ai.knowledge@1`。

## 能力

| 能力 | 含义 | 默认实现 |
| --- | --- | --- |
| `ai.chat@1` | 按名字解析 `IChatClient`；`IAIChat` 在其上叠加提示词、护栏与工具 | 无（`AI.OpenAI` 适配 OpenAI 兼容端点） |
| `ai.embedding@1` | 按名字解析 `IEmbeddingGenerator<string, Embedding<float>>` | 无（`AI.OpenAI`） |
| `ai.tools@1` | 工具目录：显式登记的 `AITool` 与 `Expose.Ai` 的操作契约桥接成的 `AIFunction` | `AI.Abstractions` 的 `AIToolsFeature`（进程内，`role: default`） |
| `ai.knowledge@1` | 知识库：`IKnowledgeIngestor` / `IKnowledgeRetriever` / `IRagPromptAugmenter`；Provider 实现 `IKnowledgeStore` | 无（`AI.VectorData` 适配应用注册的 `Microsoft.Extensions.VectorData.VectorStore`） |

公开签名只出现 `Microsoft.Extensions.AI.Abstractions` 与 `Microsoft.Extensions.VectorData.Abstractions` 的类型；具体 SDK（OpenAI、向量库连接器）只在 Provider 包里。

## Provider 目录

- 配置节 `XiHan:AI`：`DefaultProvider`、`DefaultEmbeddingProvider`（省略时同 `DefaultProvider`；只有一个 Provider 时它就是默认），`Providers:<name>` 下 `Kind`（Provider 种类，由工厂的 `Kind` 匹配，如 `openai`）、`Endpoint`、`ApiKey`、`ChatModel`、`EmbeddingModel`、`EmbeddingDimensions`、`TimeoutSeconds`（默认 100）、`Properties:<key>`（透传给工厂的字符串字典）。名字文法 `^[a-z0-9][a-z0-9._-]{0,63}$`。
- `IAIProviderCatalog`：`Providers`、`Find(name)`、`ResolveChatClient(name?)`、`ResolveEmbeddingGenerator(name?)`、`Invalidate(name?)`。解析结果按名字缓存，`Invalidate` 释放缓存实例（下次解析重建），`name` 为空时清全部；配置变化由应用调用 `Invalidate`，框架不监听。
- 名字未配置 → `AI_NOTFOUND_001`；`Kind` 没有登记对应的 `IChatClientFactory` / `IEmbeddingGeneratorFactory` → `AI_NOTFOUND_001`；缺 `ChatModel` / `EmbeddingModel` 等必填项 → `AI_VALIDATION_001`。
- Provider 包实现 `IChatClientFactory { Kind; Create(AIProviderOptions) }` 与 `IEmbeddingGeneratorFactory`，以 `AddAIChatClientFactory<T>()` / `AddAIEmbeddingGeneratorFactory<T>()` 登记；同一 `Kind` 登记两次以后者为准。

## 聊天

- `IAIChat`（作用域服务）：`CompleteAsync(AIChatRequest) → Result<ChatResponse>`、`StreamAsync(AIChatRequest) → Result<IAsyncEnumerable<ChatResponseUpdate>>`（校验、提示词与护栏在返回流之前完成）。
- `AIChatRequest`：`Messages`、`Provider`、`Prompt`（提示词名）与 `PromptArguments`、`Tools`（工具名列表，空表示不带工具）、`Options`（`ChatOptions`，`Tools` 会被目录绑定结果覆盖）、`SkipGuardrails`（默认 false）。
- 顺序：提示词渲染（不存在 → `AI_NOTFOUND_002`，参数缺失 → `AI_VALIDATION_001`）作为首条 `System` 消息 → 工具绑定（名字不存在 → `AI_NOTFOUND_003`）→ 护栏按登记顺序检查全部 `User` 消息（任一 `Block` → `AI_DENIED_001`，`details.guardrail` / `details.reason`；护栏抛异常 → `AI_UNEXPECTED_001`）→ 解析 Provider → 调用。模型端点返回错误或不可达 → `AI_UNAVAILABLE_001`，超时 → `AI_TIMEOUT_001`。
- 护栏：`IAIGuardrail { Name; InspectAsync(messages) → Result<GuardrailVerdict> }`，`GuardrailVerdict.Allow()` / `Block(reason)`；`AddAIGuardrail<T>()` 登记。内置 `KeywordBlocklistGuardrail`（`XiHan:AI:Guardrails:Enabled` 为 true 时登记）：`BlockedKeywords`（不区分大小写的子串）、`InjectionPatterns`（正则）、`UseBuiltInInjectionHeuristics`（默认 true，内置中英文提示注入模式）。直接从目录解析 `IChatClient` 的调用不经护栏。
- 提示词：`AIPromptTemplate(Name, Template, Description?)`，占位符 `{name}`，`{{` / `}}` 转义成字面量；`Render(arguments) → Result<string>`。`IAIPromptCatalog { Find(name); All() }` 合并 `AddAIPrompt(template)` 的显式登记（优先）与配置 `XiHan:AI:Prompts:<name>:Template` / `:Description`。名字文法同 Provider。

## 工具

- `Expose` 新增 `Ai = 16`，`All` 含之；插件握手的 `expose` 接受 `ai`。
- `IAIToolCatalog { All(); Find(name); Bind(InvocationContext caller) }`：`All` / `Find` 返回声明（`AIFunctionFactory.CreateDeclaration`：名字、描述、输入 / 输出 Schema）；`Bind` 返回绑定到调用方上下文的可执行工具。来源：`AddAITool(AITool)` 显式登记的工具原样返回；登记表里 `Expose` 含 `Ai` 且非 `Stability.Internal` 的操作各成一个 `AIFunction`。
- 操作工具名默认 `<resource>_<verb>`（`-` 换 `_`），`XiHan:AI:Tools:<操作 ID>` 覆盖；名字重复在构建目录时以 `AI_VALIDATION_001` 启动失败。描述取消息目录里 `<操作 ID>.description`（ID 里的 `-` 换 `_`）按调用方区域翻译，没有则为空。输入 Schema 取 `OperationSchema.Request`，没有时 `{"type":"object"}`；输出 Schema 取 `Response`。
- 调用：参数序列化成请求 JSON，在新作用域、新 `InvocationContext`（复制调用方 Baggage 与截止时间，取消令牌为调用方令牌）里经完整管道执行，Authorize 阶段按契约判定；成功返回响应 JSON，失败返回 `{"error":"<码>","message":"<按调用方区域翻译的文案>"}`——错误交给模型处理，不抛异常。

## 知识库

- 模型：`KnowledgeIngestRequest(DocumentId, Text, Collection?, Metadata?, Provider?, Chunking?)`、`KnowledgeRecord(Id, DocumentId, ChunkIndex, Text, Metadata, Vector)`、`RetrievedChunk(Record 去掉向量 + Score)`、`RetrievalFilter(DocumentIds?, Metadata?)`（元数据按键值相等过滤）、`KnowledgeQuery(Text, Collection?, Top, Filter?, Provider?, MinScore?)`、`ChunkingOptions(MaxChunkSize, Overlap)`。记录 ID 为 `<documentId>#<chunkIndex>`。
- `IChunkingStrategy.Chunk(text, options)`；内置 `FixedWindowChunkingStrategy`：按字符的固定窗口，`Overlap` 裁到 `[0, MaxChunkSize − 1]`，换行统一为 `\n`，空白块丢弃。
- `IKnowledgeStore`（Provider 契约）：`UpsertAsync(collection, records[])`、`DeleteAsync(collection, documentIds[])`、`SearchAsync(collection, vector, top, filter?) → Result<IReadOnlyList<RetrievedChunk>>`（按 Score 降序）。集合不存在：写入时创建，搜索返回空。
- `IKnowledgeIngestor.IngestAsync(requests[]) → IReadOnlyList<Result<int>>`（每篇文档的块数；同一文档重新摄入先删后写）、`RemoveAsync(collection, documentIds[])`；`IKnowledgeRetriever.RetrieveAsync(query)`；`IRagPromptAugmenter.Augment(question, chunks) → string`（`XiHan:AI:Knowledge:PromptName` 指向的提示词模板，占位符 `{context}` / `{question}`；没配置用内置英文模板）。
- 选项 `XiHan:AI:Knowledge`：`Collection`（默认 `knowledge`）、`Dimensions`（默认 1536）、`ChunkSize`（1000）、`ChunkOverlap`（100）、`Top`（5）、`EmbeddingProvider`、`PromptName`。嵌入维度与 `Dimensions` 不一致 → `AI_VALIDATION_002`；没有 `ai.knowledge` Provider 时调用摄入 / 检索 → `AI_UNAVAILABLE_002`。

## 默认实现与 Provider

- `AI.Abstractions`：`AIToolsFeature`（`xihan.ai.tools`，提供 `ai.tools@1`）与所有 AI 特性共用的 `AddAI(configuration)`（幂等）：选项、Provider 目录、`IAIChat`、提示词目录、工具目录、知识库流水线、消息目录。
- `AI.OpenAI`：`OpenAIFeature`（`xihan.ai.openai`，提供 `ai.chat@1` 与 `ai.embedding@1`）登记 `Kind = openai` 的两个工厂：`OpenAIClient`（`Endpoint` 为空时官方端点；`ApiKey` 为空时占位凭据，供本地兼容端点）→ `AsIChatClient()` → `UseFunctionInvocation()`，工具调用在客户端循环里自动执行；注册了名为 `xihan.ai.openai` 的 `HttpClient` 时经它发请求。装配与启动不触网。
- `AI.VectorData`：`VectorDataKnowledgeFeature`（`xihan.ai.vectordata`，提供 `ai.knowledge@1`，要求 `ai.embedding@1`）把 `IKnowledgeStore` 映射到应用注册的 `VectorStore`：集合定义按 `Dimensions` 构造，余弦距离；`DocumentIds` 过滤下推，元数据过滤在取回 `top × 4` 条后在进程内完成；启动时容器里没有 `VectorStore` → `AI_UNAVAILABLE_002` 启动失败。

## 一致性

Provider 继承 `KnowledgeStoreConformance`（写入、按相似度排序、文档与元数据过滤、重写入替换、按文档删除、集合隔离）与 `AIProviderConformance`（目录按名字解析聊天与嵌入、嵌入维度、`Invalidate` 后重建、未知名字 `AI_NOTFOUND_001`）并通过全部用例；套件自带确定性的 `HashingEmbeddingGenerator` 与提供 `ai.embedding@1` 的 `HashingEmbeddingFeature`。

## 错误码

`AI_VALIDATION_001`–`002`、`AI_NOTFOUND_001`–`003`、`AI_DENIED_001`、`AI_TIMEOUT_001`、`AI_UNAVAILABLE_001`–`002`、`AI_UNEXPECTED_001`，见 `conventions/error-codes.md`。消息目录 `ai`，键 `ai.*`。
